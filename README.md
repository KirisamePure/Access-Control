# 门禁系统 · Access Control

适用于 **Minecraft Java 1.21.10 / Fabric / Java 21**。客户端和服务器均需安装本模组及 Fabric API。

## 安装

将 `access-control-0.3.0.jar`（不是 `-sources.jar`）与 **Fabric API 0.138.4+1.21.10** 放入 `mods` 目录，使用 Fabric Loader 0.17.3 或更新兼容版本启动。升级时移除旧版本 JAR。

## 玩法

- **L1–L4 门禁卡**：绿色、蓝色、紫色、金色，配有不同数字与条纹，便于区分。高级卡可以通过低级门禁。
- **门禁读卡器**：放置在完整方块的侧面。手持门禁卡右键刷卡；默认要求 L1。
- **验证成功**：绿灯、提示音、物品栏上方的行动栏提示，并输出强度 15、持续 20 游戏刻（正常速度下 1 秒）的红石信号。再次成功刷卡刷新持续时间。
- **验证失败**：红灯、拒绝提示音和“权限不足”行动栏提示，不产生新的红石信号。之前已授权的脉冲仍按原计划结束。
- **配置门禁**：同时满足 **OP 权限 + 创造模式** 的玩家潜行右键读卡器，选择最低通行等级并保存。生存／冒险／旁观模式的 OP 和没有 OP 权限的创造玩家均不能修改。取消或 Esc 不修改配置；等级随世界保存。打开配置后切换回生存模式，保存请求也会被服务端拒绝。
- **生物识别门禁**：使用独立的指纹扫描器材质，贴在实体方块侧面。默认白名单为空，任何人（包括 OP）都不会自动获得通行权。白名单中的玩家双手空置后右键验证，输出强度 15、持续 20 刻的红石信号，并显示绿灯、成功提示音和行动栏提示；非白名单玩家收到红灯、拒绝音和身份不匹配提示，不产生新的信号。已有授权脉冲不会被拒绝操作提前打断。
- **生物识别配置**：创造模式 OP 潜行右键扫描器，点击玩家条目添加／移除授权（`[+]` 表示在白名单）。支持勾选在线玩家、输入在线玩家名，或输入完整 UUID 添加离线玩家；每台扫描器最多 64 人。点击保存才生效，取消保留原配置。身份按 UUID 保存，显示名只用于界面展示，白名单与世界一同保存。
- **铁制安防门**：全封闭 / 观察窗两种，像铁门一样旋转开启。
- **科技移门**：全封闭 / 观察窗两种，门板沿门侧滑动，使用 smoothstep 曲线在约 0.5 秒内开合，配有原创气动音效。根据门铰链位置决定左右滑动方向，重载区块时保持正确开关状态。
- **全玻璃科技移门**：大面积半透明蓝色玻璃，配有细窄青色灯带与触控装饰；沿侧边滑动开启。
- **工业气密科技移门**：银白外壳、橙色警示线和深色通风面板，与原有深色科技门采用不同造型。两款新增移门均有气动音效。
- **六种双格门均只接受红石控制**，普通右键不能打开。两格高，放置、破坏及上下一致性沿用原版门规则。
- **地铁双翼闸机**：参考地铁入站口的银色机柜、黑色刷卡面板、蓝色方向箭头和黄色三角翼板。手持物品点击地面，一次放置整条通道；需要横向三格、两格高的可用空间和三格实体地面。两侧机柜保留碰撞，中间通道在开启时可通过。
- **闸机控制**：可直接在机柜上刷 L1–L4 门禁卡；创造模式 OP 潜行右键任意部件可设置整台闸机的最低权限。成功刷卡开启 1 秒，低级卡只提示拒绝；也可向任意机柜或中间部件供电，红石信号保持时持续开启。双翼平滑收回机柜，带气动开关声。破坏任意部件都会移除整台闸机，不应重复掉落。
- **并排连接**：将各通道中心沿横向每隔三格放置，相邻机柜会自动以同材质连接段连成实体，堵住机柜之间的绕行空隙，无需在后面补墙。各通道仍独立配置、刷卡和开关；拆除旁边一条通道后，剩余机柜自动恢复端部外观。已有世界中符合排列条件的闸机也会自动连接，支持同向或反向排列。

### 示例接线

读卡器 → 它背后的完整方块 → 红石粉 / 中继器 → 安防门。

读卡器可以强充能背后的方块，也向周围输出弱充能。读卡器需要实体墙面支撑，不能直接贴在薄门板上。移门打开后进入相邻一格，可用墙体作为门袋；门板不会推动或破坏旁边的方块。与相邻方块碰撞体积重叠的门板会被裁掉，墙面不再和门板材质混合闪烁；台阶等非完整方块只遮挡实际覆盖的部分，露出的门板纹理不会拉伸。建议先建一个测试房间检查滑动方向，再布置墙体。

### 获取物品

创造模式“门禁系统”物品栏提供全部物品。门禁与门有工作台配方；门禁卡仅由管理员发放，避免普通玩家自行合成最高权限卡。

```mcfunction
/give @s accesscontrol:card_reader
/give @s accesscontrol:biometric_reader
/give @s accesscontrol:access_card_1
/give @s accesscontrol:access_card_2
/give @s accesscontrol:access_card_3
/give @s accesscontrol:access_card_4
/give @s accesscontrol:sealed_iron_door
/give @s accesscontrol:windowed_iron_door
/give @s accesscontrol:sliding_tech_door
/give @s accesscontrol:windowed_sliding_tech_door
/give @s accesscontrol:glass_sliding_tech_door
/give @s accesscontrol:industrial_sliding_door
/give @s accesscontrol:subway_gate
```

门和读卡器是普通可破坏方块。本模组控制刷卡和红石交互，不提供领地保护、防拆墙或防绕线功能；公共服务器可搭配领地保护插件或模组。

## 开发与验证

在仓库根目录使用完整 **JDK 21**：

```sh
./gradlew build
./gradlew runGameTest
./gradlew runClientGameTest
./gradlew runClient
```

Windows 使用 `gradlew.bat`。构建产物位于 `build/libs/`。JUnit 检查权限矩阵、动画曲线、几何裁剪的面积与 UV，以及白名单输入校验；`runGameTest` 在真实 Minecraft 服务端中验证各游戏模式的 OP 配置限制、生物识别与白名单持久化、连续脉冲定时、六种门的双格红石行为，以及闸机的结构、刷卡、红石和拆除。`runClientGameTest` 需要图形环境，验证模型渲染、白名单勾选与 UUID 输入、验证反馈、潜行配置，以及打开界面后切换生存模式不能保存等网络检查，并验证移门墙体遮挡和闸机连接；截图保存在 `build/run/clientGameTest/screenshots/`。GameTest 的测试模组不会打包进发行 JAR。

首次 GameTest 会在专用测试目录生成并接受 Minecraft EULA；运行前请阅读 https://aka.ms/MinecraftEULA 。

原始 PNG / OGG 和 JSON 资源均已随仓库提交，正常构建不需要额外资源工具。需要重新生成资源时，安装 Pillow 与 ffmpeg，再运行：

```sh
python tools/generate_assets.py
```

素材均为本项目程序绘制 / 合成，没有额外美术或音效下载依赖。支持简体中文与英文。

### 手动验收

1. 使用 L1 卡刷 L4 门禁，检查红灯、拒绝声、行动栏提示且门未打开；使用 L4 卡，检查绿灯、成功声、门开启后自动关闭。
2. 创造模式 OP 潜行右键，分别设置 L1–L4；退出并重进世界，检查配置仍存在。生存 OP、非 OP 创造玩家都不能打开或保存配置。
3. 在多人服务器中测试非 OP、非创造模式、距离超过 8 格或跨维度的配置请求被拒绝。
4. 分别测试四个方向与两种铰链的门：上下半格通电都可开门，断电关闭；普通右键无效；破坏任意半格不重复掉落。
5. 检查两种观察窗透明、四张卡外观不同；移门开合平滑、开合途中反向不发生位置跳跃，音效与字幕正常。
6. 生物识别门禁保存两名玩家后，用白名单玩家和非白名单玩家分别空手验证；测试主手或副手拿物品不能触发。移除玩家并重进世界，确认授权已撤销。打开配置后切换生存模式，确认无法保存修改。

自动测试与人工客户端验收覆盖不同内容；请在实际游玩环境中最终确认音量、手感及与其他模组的兼容性。
